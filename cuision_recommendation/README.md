# 냉장고 미니홈피

냉장고 사진을 바탕으로 지금 가진 재료를 확인하고, **조리 시간이 짧고 설거지가 적은 요리**를 추천하는 모바일 웹앱 프로토타입입니다.

퇴근 후 “오늘 뭐 먹지?”를 고민하며 레시피를 검색하는 시간을 줄이는 것이 이 프로젝트의 목표입니다. 현재 버전은 실제 이미지 인식 API 없이 샘플 재료를 반환해, 사진 선택부터 요리 완료와 재고 반영까지의 전체 사용자 흐름을 체험할 수 있도록 구성되어 있습니다.

## 주요 기능

- 알레르기, 기피 음식, 싫어하는 재료, 식단 및 보유 조리도구 설정
- 카메라 촬영 또는 앨범 이미지 선택
- 약 1.3초 동안의 사진 분석 UI와 결정론적인 샘플 인식 결과
- 인식된 재료의 이름, 남은 양, 유통기한 추가·수정·삭제
- 보유 재료와 조리도구를 만족하는 레시피를 최대 3개 추천
- 조리 시간, 설거지 수, 임박 재료, 과거 평가를 반영한 추천 정렬
- 한 단계씩 확인하는 조리법과 단계별 타이머
- 요리 완료 후 사용 재료의 재고 반영 및 만족도 평가
- 설정, 재고, 완료 기록, 평가의 브라우저 로컬 저장
- PWA 매니페스트와 서비스 워커를 통한 정적 자산 캐싱
- 지원 브라우저에서 사용할 수 있는 WebMCP 도구 2종

## 사용자 흐름

```text
내 식탁 설정
  → 냉장고 사진 촬영/선택 또는 샘플 체험
  → 인식 결과 확인 및 재료 편집
  → 추천 메뉴 확인
  → 단계별 조리 및 타이머 사용
  → 사용 재료를 재고에 반영
  → 메뉴 평가
```

처음 방문하면 식탁 설정 창이 열립니다. 조리도구를 선택하지 않으면 가스레인지와 전자레인지가 기본값으로 적용됩니다.

## 추천 방식

추천 후보는 다음 조건을 모두 만족해야 합니다.

1. 레시피의 핵심 재료를 모두 보유하고 있어야 합니다.
2. 설정한 조리도구 중 하나로 만들 수 있어야 합니다.
3. 알레르기, 먹지 못하는 음식, 싫어하는 재료에 해당하지 않아야 합니다.

소금, 식용유, 간장은 기본적으로 보유한 양념으로 간주합니다. 후보는 아래 순서로 정렬한 뒤 상위 3개만 표시합니다.

1. 예상 조리 시간 오름차순
2. 예상 설거지 수 오름차순
3. 3일 이내 유통기한이 도래하는 재료의 활용 개수 내림차순
4. 사용자의 과거 평가 점수 내림차순

현재 포함된 샘플 레시피는 간장계란밥, 전자레인지 치즈계란찜, 두부김치 한 그릇, 원팬 김치볶음밥입니다.

## 실행 방법

별도의 빌드나 패키지 설치가 필요 없는 정적 웹앱입니다. 서비스 워커와 브라우저 기능이 정상 동작하도록 `dist` 디렉터리를 로컬 HTTP 서버로 제공하는 방식을 권장합니다.

### Python 사용

```bash
cd app/dist
python -m http.server 8000
```

브라우저에서 <http://localhost:8000>을 엽니다.

### Node.js 사용

```bash
npx serve app/dist
```

명령 실행 후 터미널에 표시되는 로컬 주소로 접속합니다.

모바일 카메라 입력은 브라우저와 기기의 지원 여부에 따라 파일 선택 화면으로 대체될 수 있습니다. 로컬 네트워크의 다른 기기에서 접속할 경우 일부 브라우저 기능은 HTTPS 보안 컨텍스트를 요구할 수 있습니다.

## 데이터 저장

사용자 상태는 브라우저 `localStorage`의 `fridge-mini-v1` 키에 저장됩니다.

- 온보딩 완료 여부와 식탁 설정
- 현재 재료와 수량·유통기한
- 메뉴별 긍정·부정 평가
- 완료한 레시피와 현재 화면 상태

선택한 사진은 영구 저장하지 않습니다. 화면 미리보기를 위한 객체 URL로만 사용하며, 저장 상태에서는 제외됩니다. 타이머 실행 상태도 새로고침 후 이어지지 않습니다.

저장 데이터를 초기화하려면 브라우저 개발자 도구에서 해당 사이트의 로컬 저장소를 삭제하거나 다음 코드를 실행합니다.

```js
localStorage.removeItem("fridge-mini-v1");
location.reload();
```

## WebMCP 지원

브라우저가 `document.modelContext.registerTool`을 제공하면 앱은 다음 도구를 등록합니다.

| 도구 | 설명 |
| --- | --- |
| `start_sample_fridge_scan` | 샘플 재료를 생성하고 재료 확인 화면으로 이동합니다. |
| `get_current_fridge` | 현재 냉장고의 재료명, 수량, 유통기한을 읽습니다. |

일반 브라우저에서는 WebMCP API가 없어도 앱의 기본 기능을 그대로 사용할 수 있습니다.

## 현재 프로토타입의 한계

- 업로드한 사진을 실제로 분석하지 않고 항상 같은 샘플 재료를 생성합니다.
- 레시피 데이터는 `app.js`에 정의된 4개 샘플로 제한됩니다.
- 식단 제한 입력값은 저장되지만 현재 추천 필터에는 직접 적용되지 않습니다.
- 재고 반영 시 “전부 사용”한 재료만 목록에서 제거하며, “일부 사용” 수량을 계산해 차감하지는 않습니다.
- 백엔드, 사용자 계정, 여러 기기 간 동기화, 운영용 데이터베이스는 없습니다.
- 자동화된 테스트와 별도의 빌드·린트 스크립트는 아직 포함되어 있지 않습니다.
- 서비스 워커는 캐시 우선 방식이므로 배포 파일을 변경할 때 `sw.js`의 캐시 버전을 함께 갱신해야 즉시 반영하기 쉽습니다.

향후 요구사항과 검증 시나리오는 [`PRD.md`](./PRD.md)에서 확인할 수 있습니다.
